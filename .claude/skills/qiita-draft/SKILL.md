Adacchi3 の Qiita 記事（https://qiita.com/Adacchi3 ）の草案を作成・推敲する。

## 手順

1. 記事にする対応内容（PR、コミット、会話の経緯）を確認する
2. 必要に応じて https://qiita.com/Adacchi3 の過去記事をいくつか読み、文体と章立てを合わせる
3. 草案を scratchpad に Markdown で書き、ユーザーに渡す
4. 指摘を受けたら、下のチェック事項に照らして全体も見直してから渡し直す

## 書式

- 先頭に HTML コメントでタイトルとタグを書く

  ```markdown
  <!--
  タイトル: Apollo Client 4 で typescript-react-apollo から typed-document-node に移行した
  タグ: GraphQL, apollo, graphql-codegen, TypeScript, Next.js
  -->
  ```

- 文体は「です・ます」調
- 章見出しは `#`、節見出しは `##` を使う
- URL は単独の行に置き、Qiita のリンクカードとして表示させる
- 公式ドキュメントの記述は英語のまま `>` で引用し、出典の URL を添える
- コードブロックにはファイル名を付ける（例: ` ```ts:src/types/top.ts `、` ```diff_tsx:AboutUs.tsx `、` ```yaml:codegen.yml `）
- 関連する自分の過去記事やソースコードのリポジトリは、「はじめに」でリンクする

## 章立て

```markdown
# はじめに
背景・経緯（関連する過去記事へのリンク）、ソースコードへのリンク

# （本題の章）
例: 移行する理由 / 移行方法の比較 / 移行手順

# おわりに
要点の箇条書きと、所感

# 参考
- [ページタイトル \| サイト名](URL)
```

## チェック事項

### 構成

- [ ] 「はじめに」で始めたら、締めは「まとめ」ではなく「おわりに」にしている
- [ ] 「環境」の節を設けていない
- [ ] 主題でない話題（今後やりたいことなど）を「おわりに」に入れていない
- [ ] Claude のローカル環境でしかできない動作確認手順を載せていない

### 表現

- [ ] 「ハマりどころ」のような飾った言葉を使っていない
- [ ] 「その場しのぎ」という言葉を使っていない
- [ ] 読者が知らない固有名詞（例: The Guild）を説明なしに出していない。「調べたら移行先が複数あった」程度にとどめる
- [ ] ユーザーが伝えた言葉をそのまま貼らず、記事の文章や文体に合わせて書き直している
- [ ] 「おわりに」の所感が、ありきたりな教訓になっていない。ユーザーが違和感を示したら、別の観点に書き直す

### 正確さ

- [ ] 「〜で推奨されている」と書くときは、どのページが推奨しているかを確かめ、原文を引用している
- [ ] 記事の書き手や公開元（公式か個人か）を確かめ、そのとおりに書いている
- [ ] 出典が公式でなくても、内容が確かなら URL や記述は削らずに残している
- [ ] バージョン番号や数値（行数など）は、実際のファイルやパッケージで確かめている
